# 순차형 타이핑 커서 모양 변경 설계

## 목표

글자가 작성될 때 현재 입력 위치의 커서 모양이 정해진 순서로 바뀌도록 한다. 기존 타이핑, 한글 자모 조합, 자동 타이핑, 타격 효과, 리셋 기능은 유지한다.

## 범위

- 수정 파일: `index.html`
- 기존 `#cursorAnchor` 요소를 유지한다.
- 외부 라이브러리, 빌드 도구, 별도 런타임 의존성은 추가하지 않는다.
- 커서 모양 변경은 실제 입력과 자동 타이핑에 공통 적용한다.
- 커밋과 push는 사용자의 화면 확인 전에는 하지 않는다.

## 접근안

1. CSS 도형 순환(선택)
   - 커서 DOM 요소 하나의 상태 속성 또는 클래스를 작성 이벤트마다 변경한다.
   - CSS가 상태별 모양을 표현한다.
   - 기존 입력 위치 측정과 타격 효과를 그대로 재사용할 수 있어 영향 범위가 작다.

2. DOM 요소 교체
   - 작성마다 커서 요소를 새로 만들고 교체한다.
   - 모양별 애니메이션은 유연하지만, 기존 위치 측정 및 이벤트와 동기화할 지점이 늘어난다.

3. SVG path 변경
   - SVG 한 요소 안의 path를 순환한다.
   - 시각 제어력은 높지만 현재 단일 HTML 구조에 비해 복잡도가 커진다.

## 상세 설계

### 커서 상태

- `cursorShapeIndex`를 화면 상태로 둔다.
- 작성 이벤트가 발생할 때마다 순환 인덱스를 증가시킨다.
- CSS 상태 순서는 세로 막대, 밑줄, 사각형 테두리, 점 형태로 고정한다.
- 인덱스는 범위를 넘으면 첫 상태로 돌아온다.

### 입력 이벤트 연결

- 실제 키 입력과 자동 타이핑이 공유하는 작성 처리 지점에서 커서 상태를 갱신한다.
- 한글 자모가 조합 중이어도 글자 작성 피드백이 보이도록 현재 커서 모양을 갱신한다.
- 백스페이스, 리셋, 조합 flush는 기존 동작을 보존하고 커서 상태는 다음 작성에서 계속 순환한다.
- 커서의 DOM 위치와 텍스트 렌더링은 변경하지 않아 `getBoundingClientRect()` 기반 타격 효과와 호환한다.

### 스타일 및 접근성

- `#cursorAnchor`의 기존 inline-block 역할을 유지한다.
- 모양별 CSS는 입력 위치를 흔들지 않도록 동일한 기준 박스 안에서 표현한다.
- `prefers-reduced-motion`에서는 모양 변경 자체는 유지하고, 전환 애니메이션만 제거하거나 최소화한다.
- 커서는 장식 요소이므로 기존처럼 텍스트 입력 보조 역할을 방해하지 않는다.

### 검증

1. 정적 검사: `index.html`의 태그·스크립트 구조가 손상되지 않았는지 확인한다.
2. 서버 실행: `python3 -m http.server 8000`으로 프로젝트 루트를 서비스한다.
3. 브라우저 확인: Windows 브라우저에서 `http://localhost:8000`에 접속해 키 입력과 자동 타이핑 시 커서 모양 순환을 확인한다.
4. 기존 기능 확인: 한글 조합, 백스페이스, 리셋, 자동 타이핑, 램프 및 타격 효과가 유지되는지 확인한다.
5. Git 확인: 변경 파일과 브랜치를 확인하되, 사용자가 요청하기 전에는 커밋·push하지 않는다.

## 완료 기준

- 글자가 작성될 때마다 커서 모양이 위 순서대로 바뀐다.
- 실제 입력과 자동 타이핑 모두에서 동작한다.
- 기존 기능에 회귀가 없다.
- 로컬 서버가 포트 8000에서 실행되고 Windows 브라우저 접속 주소를 안내할 수 있다.
